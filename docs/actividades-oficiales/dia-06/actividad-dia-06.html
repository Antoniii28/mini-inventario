Automatiza las pruebas con GitHub Actions

Hoy logras que cada pull request se pruebe solo. También provocas una falla para que el agente la diagnostique desde la terminal.

Duración: 60 minutosModalidad: individual

Antes de empezar

  • Las pruebas de Playwright en la rama principal.
  • Tu repositorio debe seguir público.

Herramientas que necesitas

HerramientaPara qué sirveCosto
Claude Code o CodexEl agente con el que haces toda la actividad. Usa el que ya tengas.Codex viene en ChatGPT Free
Git y GitHubGuardar versiones y publicar tu repositorio.Gratis
GitHub CLI (gh)Que el agente trabaje con GitHub desde la terminal.Gratis
GitHub ActionsCorrer las pruebas en cada pull request.Gratis en repositorio público
Playwright TestPruebas automáticas que se guardan en el proyecto.Gratis
Supabase (plan Free)Base de datos PostgreSQL e inicio de sesión.Gratis, 2 proyectos activos

Qué tienes que hacer

  1. Crea la rama5 min

    Crea dia-06-ci y confirma que npx playwright test pasa en tu computadora.

  2. Guarda los secretos10 min

    Ejecuta estos comandos tú mismo y escribe cada valor cuando te lo pida. No pegues llaves ni contraseñas en la conversación con el agente.

    Terminal
    gh secret set SUPABASE_URL
gh secret set SUPABASE_KEY
gh secret set TEST_EMAIL
gh secret set TEST_PASSWORD
gh secret list

  3. Crea el flujo de trabajo15 min

    Revisa que el archivo no contenga valores secretos escritos directamente.

    Prompt para tu agente
    Crea .github/workflows/ci.yml para que en cada pull request hacia main se ejecute en ubuntu-latest con Node 22: npm ci, instalación de Chromium con sus dependencias y las pruebas de Playwright. Pasa como variables de entorno los secretos SUPABASE_URL, SUPABASE_KEY, TEST_EMAIL y TEST_PASSWORD. Sube el reporte de Playwright como artefacto. Después abre un pull request con gh.

  4. Pasa de verde a rojo y otra vez a verde20 min

    Espera a que el PR pase. Sube un cambio que rompa una prueba y espera a que falle. Toma captura de ambos estados y pide el diagnóstico sin dar pistas.

    Prompt para tu agente
    Las verificaciones de este pull request fallaron. Usa gh pr checks, gh run list y gh run view con --log-failed para encontrar la causa. Explícamela antes de corregir. Cuando la apruebe, corrige, sube el cambio y comprueba que todo pase.

  5. Explica lo que pasó10 min

    Escribe en tu bitácora la causa de la falla con tus palabras. Después haz merge del PR.

Qué entregas

Enlace al pull request, con capturas y entregas/dia-06/README.md.

  • Los prompts clave que usaste.
  • Un error o una mala decisión de la IA, y cómo lo detectaste.
  • Un comando o herramienta que aprobaste o rechazaste, y por qué.
  • Cómo comprobaste que funciona.

Si te atoras

Si la prueba falla solo en GitHub, compara nombres de secretos y variables, y revisa el reporte de Playwright.

Si terminas antes

Protege main para que exija la verificación antes de hacer merge.
