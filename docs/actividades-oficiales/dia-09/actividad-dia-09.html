Publica tu app y diagnostica un despliegue fallido

Hoy empaquetas tu aplicación, la publicas en Render con una URL real y usas el MCP de Render para leer una falla como lo harías en producción.

Duración: 60 minutosModalidad: individual

Antes de empezar

  • La rama principal con pruebas en verde.
  • Una cuenta gratuita de Render.
  • Docker instalado y en ejecución.

Qué tienes que hacer

  1. Prueba el contenedor en local15 min

    Crea el Dockerfile en una rama, pruébalo, abre el PR y haz merge cuando el CI pase.

    Prompt para tu agente
    Crea un Dockerfile para Mini Inventario y un .dockerignore que excluya .env, node_modules, tests y entregas. La app debe escuchar en 0.0.0.0 y en process.env.PORT. No copies secretos a la imagen. Explícame cada instrucción.
    Terminal
    docker build -t mini-inventario .
docker run --env-file .env -e PORT=3000 -p 3000:3000 mini-inventario

  2. Crea el servicio en Render15 min

    Ve a New y Web Service. Conecta tu repositorio, elige Language: Docker y el plan Free. Agrega SUPABASE_URL y SUPABASE_KEY y deja Auto-Deploy en On Commit. Inicia sesión en la URL pública y toma una captura.

  3. Conecta el MCP de Render5 min

    Sigue la sección de tu agente en la documentación del MCP de Render. No cambies variables de entorno desde el MCP: hazlo en el panel y aprueba cada despliegue manualmente.

  4. Provoca y diagnostica una falla20 min

    Agrega a main una línea RUN npm run no-existe en el Dockerfile y espera el despliegue fallido. Pide el diagnóstico. Si el MCP no conecta, lee los logs en el panel y documenta el error de conexión.

    Prompt para tu agente
    Usa el MCP de Render para listar el último despliegue de mi servicio y leer sus logs. Explícame la causa exacta de la falla y qué línea la provocó. No cambies variables ni lances despliegues sin preguntarme.

  5. Repara y verifica5 min

    Quita la línea, espera el despliegue correcto y comprueba la URL con el agente. Guarda la evidencia en entregas/dia-09/.

Qué entregas

URL pública y entregas/dia-09/README.md con capturas.

  • Los prompts clave que usaste.
  • Un error o una mala decisión de la IA, y cómo lo detectaste.
  • Un comando o herramienta que aprobaste o rechazaste, y por qué.
  • Cómo comprobaste que funciona.

Si te atoras

El servicio se duerme tras 15 minutos sin tráfico y tarda cerca de un minuto en despertar. Render asigna el puerto 10000 de forma predeterminada.

Si terminas antes

Agrega una verificación de salud con la ruta /health en la configuración del servicio.
