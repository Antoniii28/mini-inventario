Resuelve un incidente de principio a fin

Hoy das una vuelta completa al ciclo de vida: un reporte llega desde producción, lo investigas, escribes una prueba, lo corriges y verificas la solución publicada.

Duración: 60 minutosModalidad: individual

Antes de empezar

  • La app publicada en Render.
  • El MCP de Supabase, el MCP de Render, las pruebas y el CI funcionando.

Reporte recibido

«Pude guardar un producto con cantidad -5. La lista lo muestra como si nada y el inventario queda mal.» Si tu app ya lo bloquea, usa este reporte: «Pude registrar dos productos con el mismo SKU».

Qué tienes que hacer

  1. Lee el reporte5 min

    Abre la URL pública con un minuto de anticipación para despertar el servicio. Escribe qué crees que ocurre antes de pedir ayuda.

  2. Reproduce e investiga10 min

    Confirma el problema en producción y guarda la captura.

    Prompt para tu agente
    Tenemos este reporte de producción: [pega el reporte]. Usa playwright-cli en la URL pública para reproducirlo y toma una captura. Revisa los logs recientes con el MCP de Render y consulta los datos con Supabase en solo lectura. Explica la causa. No cambies nada todavía.

  3. Abre el issue5 min

    Pide crear el issue con gh. Debe incluir pasos para reproducir, causa y criterios de aceptación.

  4. Escribe primero la prueba10 min

    En la rama dia-10-incidente, pide una prueba de Playwright que reproduzca el reporte. Córrela y guarda la evidencia de que falla.

  5. Corrige en la web y en la base15 min

    La protección debe estar en ambos lugares. Revisa el SQL y qué ocurre con los datos incorrectos ya guardados.

    Prompt para tu agente
    Corrige el issue validando el dato en la web y agregando una restricción en la base con una migración mediante el MCP de Supabase. Primero muéstrame cuántas filas incumplen la regla y propón qué hacer con ellas. Espera mi aprobación antes de modificar datos o aplicar el SQL. Después corre las pruebas.

  6. Publica y verifica10 min

    Abre el pull request que cierre el issue. Haz merge cuando el CI pase, espera el despliegue y repite el caso en la URL pública para confirmar que ya no ocurre.

  7. Cierra el ciclo5 min

    Escribe qué aprendió el sistema con este incidente y cuál sería el siguiente requisito. Anota también qué le delegarías a un agente y qué seguirías revisando tú.

Qué entregas

Enlaces al issue, al pull request y a la URL pública, con entregas/dia-10/README.md.

  • Los prompts clave que usaste.
  • Un error o una mala decisión de la IA, y cómo lo detectaste.
  • Un comando o herramienta que aprobaste o rechazaste, y por qué.
  • Cómo comprobaste que funciona.

Si te atoras

Si la restricción falla, probablemente aún existen filas incorrectas. Resuelve esas filas primero.

Si terminas antes

Si usas Claude Code, crea un mod de barra de estado con la rama y los cambios pendientes.
