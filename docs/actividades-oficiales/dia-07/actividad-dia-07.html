Enséñale a tu agente cómo trabaja tu proyecto

Hoy escribes una skill con las reglas de pruebas y un subagente que revisa sin modificar. Vas a medir si realmente cambian el resultado.

Duración: 60 minutosModalidad: individual

Antes de empezar

  • Las pruebas y el CI funcionando.

Herramientas que necesitas

HerramientaPara qué sirveCosto
Claude Code o CodexEl agente con el que haces toda la actividad. Usa el que ya tengas.Codex viene en ChatGPT Free
Git y GitHubGuardar versiones y publicar tu repositorio.Gratis
GitHub CLI (gh)Que el agente trabaje con GitHub desde la terminal.Gratis
Playwright TestPruebas automáticas que se guardan en el proyecto.Gratis

Qué tienes que hacer

  1. Haz el pedido sin skill10 min

    En una rama dia-07-skill y conversación limpia, pide: «Escribe una prueba de Playwright para editar un producto». Guarda el código en tu bitácora y descarta el archivo generado.

  2. Escribe la skill15 min

    Crea la skill pruebas-inventario en la ruta de tu agente. Revísala y deja una descripción que indique cuándo usarla.

    Prompt para tu agente
    Crea una skill llamada pruebas-inventario en la ruta correcta para este agente. Debe indicar: usar Playwright en tests/, leer credenciales del entorno, usar un SKU único por prueba, borrar lo creado, seleccionar elementos por rol o etiqueta, y cubrir el caso correcto y un caso de error. La descripción debe activarse cuando se pidan pruebas de Mini Inventario.

  3. Repite el mismo pedido10 min

    Abre una conversación limpia y pide exactamente lo mismo. Compara con el primer resultado: qué mejoró, qué sigue mal y cuánto tuviste que corregir.

  4. Crea un subagente revisor15 min

    Debe llamarse revisor-pr, usar la ruta de tu agente y no modificar archivos. Ejecútalo sobre esta rama y confirma con git status que no cambió nada.

    Prompt para tu agente
    Crea un subagente llamado revisor-pr en el formato correcto para este agente. Su trabajo es revisar git diff main en busca de secretos, cambios sin pruebas y consultas sin protección por usuario. Debe responder con una lista de hallazgos, archivo y gravedad. No debe modificar archivos ni ejecutar comandos que cambien el proyecto.

  5. Entrega con evidencia10 min

    Atiende un hallazgo o explica por qué no aplica. Abre el pull request con la skill, el subagente y tu comparación.

Qué entregas

Enlace al pull request, con la comparación en entregas/dia-07/README.md.

  • Los prompts clave que usaste.
  • Un error o una mala decisión de la IA, y cómo lo detectaste.
  • Un comando o herramienta que aprobaste o rechazaste, y por qué.
  • Cómo comprobaste que funciona.

Si te atoras

Si la skill no se activa, mejora su descripción con palabras parecidas a tu pedido.

Si terminas antes

Agrega una automatización que formatee los archivos tras cada edición, si tu agente la admite, o empaqueta lo creado como plugin.
